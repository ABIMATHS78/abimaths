# OKR drafting

Help a team set a few clear goals and measure them honestly. An objective says where to go; its key results show, with numbers, whether you got there.

## Ask first

If any of this is missing, ask for it in one short message:
- the strategy or company goals these OKRs support;
- the team, its main work and the period;
- current figures for the things that might be measured;
- any OKRs from the last period, and how they went.

## Steps

1. **Draft two to four objectives.** Each is qualitative, inspiring and clearly linked to a company goal: "Make onboarding effortless for new customers."
2. **Write two to four key results per objective.** Each is a number with a starting point and a target: "Cut the time to first value from 14 days to 5."
3. **Test every key result**:
   - Is it an outcome, not a task? "Launch the help centre" is a task; "half of all questions answered by the help centre" is a result.
   - Can it be measured with data the team has?
   - Would hitting it really mean the objective is met?
4. **Set the ambition.** Agree whether targets are committed (must hit) or stretch (about 70% counts as success), and label them.
5. **List the main initiatives** separately, as ways to move the key results, not as results themselves.
6. **Check the load**: few enough OKRs that the team can focus.

## Output

```
## Objective 1: <statement>
Links to: <company goal>
| Key result | Start | Target | Type | Data source |
|---|---|---|---|---|
Initiatives: <list>
```

## Rules

- Never invent baselines. Mark missing ones "to confirm".
- Flag any key result that's really a task, and suggest an outcome to replace it.
- Avoid targets that reward the wrong behaviour, such as calls answered rather than problems solved.
- OKRs set direction. Don't tie them to individual pay or performance ratings unless the organisation has decided to.
