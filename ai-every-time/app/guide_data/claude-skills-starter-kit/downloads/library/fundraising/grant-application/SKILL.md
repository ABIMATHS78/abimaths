# Grant application

Draft an application that answers exactly what the funder asks, in their order and within their limits, so an assessor can score it easily.

## 1. Get what you need

If anything below is missing, ask for it in one short message. Mark smaller gaps "to confirm" and carry on.
- the funder's guidance, questions, scoring criteria and limits, copied in full;
- the project: the need, activities, who benefits, outcomes, timeline, budget, team and partners;
- evidence: data on the need, past results, evaluations, feedback given with consent;
- the organisation's details (legal form, registration, income, track record) and the deadline.

## 2. Check eligibility first

Go through each criterion (location, type of organisation, income, kind of project, exclusions) and say where the project fits. If there's a clear mismatch, say so before drafting anything.

## 3. Map questions to criteria

Pair each question with the criteria it's scored on and the evidence you'll use. Use the funder's terms for their priorities where they honestly fit, but don't stuff them in.

## 4. Draft each answer

- Answer the question in the first sentence.
- **Need**: who, where and how many, with sourced evidence; why now; why this organisation.
- **Activities**: what, how often, for whom, and delivered by whom.
- **Outcomes**: the changes for people, and how you'll measure them. Keep outputs (what you do) apart from outcomes (what changes).
- **After the grant**: what continues, and how it will be paid for.
- Use plain words, the active voice and specific detail.

## 5. Fit the limits and check

Count words or characters the way the funder counts them, including whether spaces count. Stay under each limit, and show the count. Then check that beneficiary numbers, costs and dates match across every answer and the budget.

## 6. Return the draft

```
## Eligibility check
| Criterion | Our position | Fits? |
|---|---|---|

### Q<n>. <question exactly as the funder wrote it>
Limit: <limit> | Count: <count>
<answer>
Criteria covered: <criteria>
Evidence used: <source, or "to confirm">

## To confirm before submitting
- <gap>
```

## Rules

- Never invent figures, outcomes, case studies, quotes, partners, letters of support or evaluation findings. Mark gaps "to confirm".
- Don't overclaim. Funders compare later reports with what the application promised.
- Use people's stories only with informed consent, anonymised where needed, under the safeguarding and data-protection rules where the organisation works.
- Follow the funder's instructions exactly, including any rules they set on using AI tools.
- Never copy another organisation's application text.
