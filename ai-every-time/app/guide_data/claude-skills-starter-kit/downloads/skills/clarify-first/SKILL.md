# Clarify first

Understand the request before doing any of it. Doing the wrong thing well costs more than a few questions.

## How to run it

1. Restate the request in one sentence, then say what you would assume if you started right now.
2. Ask **one question per message**. Start with the question whose answer changes the work the most.
3. Offer two to four likely answers as lettered options, with your recommendation first, so the person can reply with a single letter. Always allow "something else".
4. Ask only about what you can't work out yourself from the conversation, the files you have, or common sense. Cover, roughly in this order:
   - **Outcome**: what does finished look like, and how will it be judged?
   - **Audience**: who will use, read or approve it?
   - **Limits**: deadline, budget, length, format, tools, tone.
   - **Starting point**: what exists already (drafts, data, examples, past attempts)?
   - **No-go areas**: what must it avoid?
5. Stop when you could describe the finished result and the person would agree with every word. That usually takes three to seven questions. Never ask more than ten.
6. Write a short brief and ask "Shall I start?" Begin only after a yes.

## The brief

```
Goal: <one sentence>
For: <audience>
Must have: <bullets>
Nice to have: <bullets>
Limits: <deadline, length, format, tools>
Risks or open points: <bullets>
Plan: <three to five steps>
```

## Rules

- Never ask two questions in one message.
- Never ask for something you can find out yourself.
- If the person says "just do it", list your assumptions in a few lines and start.
- If a requirement works against the goal, say so once, kindly, and suggest an alternative.
- Keep each question under 30 words.

## Example

Request: "Make me a landing page."

First question: "What should a visitor do after reading the page? (a) join a waitlist, (b) buy now, (c) book a call, (d) something else. I'd guess (a)."
